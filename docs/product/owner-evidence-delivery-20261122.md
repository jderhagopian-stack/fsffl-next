# Finish the existing owner intelligence journey

## Reconciled scope

This continues the existing platform; it does not begin a new behavioral model.
The production baseline is PR #588. Completed-history lookup/restore and package
binding, strategic search tie-breaking and the counteroffer precedent lane are
already implemented. Manual objectives and native team/position economics stay
in control. Counts describe completed deals, not rejection, preference or odds.

## This bounded increment

The shared package-history result adds typed observations from its existing
trade-only aggregates. Keep the legacy prose and matching-feature list intact.
Give pick and position evidence priority over generic asset-count shape when
rendering the existing history details. State whether a count describes players
or trades. Both owner viewpoints use explicit subject/pronoun templates; old
saved results remain readable. Missing precedents never mean unwillingness.

Example: “They have traded for draft picks in 4 of 10 completed trades. This
offer brings them more picks.” This is useful precedent, not evidence that they
prefer rebuilding or will accept. Current needs and timeline still come from
Decision and remain distinct from observed behavior.

No new provider request, fit, historical recomputation, database write/adapter,
service or recurring expense. Only a bounded additive result from the already
loaded profile; the existing UI displays up to three relevant observations.
No change to search ordering, proposal economics, disposition or valuation.

## Acceptance and next dependencies

Focused tests protect trade-only counts, legacy profiles, future-profile and
wrong-State rejection, exact matching features, search priority dominance,
restart/API consumption, both perspectives and player-versus-trade units.
Use one stable-head full suite before merge. Hosted display and physical mobile
acceptance remain distinct from these tests; no expensive refresh is needed for
this explanation change. Older saved search results retain their existing text
until an ordinary new search/evaluation generates the additive observations.

Next validate a bounded owner journey using already published intelligence:
search with automatic and directed priorities, inspect both teams, change the
package and request a counter. Classify relevance, stale evidence, language and
interaction failures separately. Fix demonstrated blockers together rather than
starting a new analytics framework. Then reuse historical field coverage for a
chronological preference-readiness experiment; publish no weights until its
held-out evidence supports them. Historical outcome grading can progress using
observed results without waiting for nonexistent old forecasts. Reports follow
supported content, rather than replacing completion of this journey.
